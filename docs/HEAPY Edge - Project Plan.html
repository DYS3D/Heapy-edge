HEAPY EdgeProject Plan

OwnerJustin Cross
Started2026-09-29
Statusv0.1.0 · Phases 0–1 built

HEAPY's own on-site data collector, the long-term replacement for Novant. A small site box (a Raspberry Pi, an industrial mini-PC or a client VM) plugs into the client network, finds the BAS devices, reads their points on a schedule and sends the readings to a central HEAPY Trend Tracker server, where naming, FDD, alerts and reports already work. Every piece is built so more protocols, destinations and connection types can be added later without rework.

Architecture

How the pieces fit

Decisions

How it's built

ModelSite box plus central server (decided 2026-09-29). The site box only collects, buffers and uploads. Everything else runs centrally in Trend Tracker. Full on-site mode is designed in from day one and turned on later for clients whose data can't leave the site.
PlatformOne Docker image for 64-bit ARM and x86 Linux, so the same build runs on a Raspberry Pi 5, an industrial mini-PC or a client Linux VM. A ready-to-flash box image for HEAPY-supplied hardware. A Windows build only if a client requires it.
LinkOutbound HTTPS on port 443 to one HEAPY hostname. No inbound firewall rules. Works through client proxies. Setup changes, point list edits and updates come back over the same connection. A VPN (WireGuard) is an optional add-on per site, only where a client approves it.
SafetyRead-only: the box never writes to a BAS device, never changes BACnet routing or BBMD tables, and never overrides. Scans are throttled, run in set time windows and can be limited to address ranges. Each device has a request-rate limit so the box can't flood a slow controller or an MS/TP trunk.
StackBox core in Node 24 (same language as Trend Tracker, node:sqlite buffer). Protocol drivers are separate programs so each can use the best open-source library for its protocol, e.g. bacnet-stack (C: BACnet/IP, MS/TP, ARCNET) or BACpypes3 (Python). Licenses are checked in Phase 0 before a library is picked.
Storage on the boxSQLite buffer that keeps readings until the server confirms it has them, plus a rolling 30 days (setting) for re-sends. A 256 GB SSD holds years of one site's data. Pi boxes boot from SSD, not an SD card.
PollingDefault 15 minutes per point (matches Novant), 1–5 minutes for chosen points, and change-of-value subscriptions where the device supports them. Batched reads (ReadPropertyMultiple) to keep traffic low.
SecurityEach box is paired with a one-time code and gets its own key. The server can revoke it. TLS on every upload. Updates are signed, and the box checks the signature before installing. The local setup page is on the box's own network only, behind a password.
NetworksTwo network ports supported: one on the BAS network, one on a network with internet access. This keeps the BAS network cut off from the internet, which many client IT teams ask for. One port works where the BAS network already has an internet path.
Built to extend

Where new methods plug in

Four fixed contracts keep additions separate from the core. A new protocol, destination or connection type is a new module that follows its contract. Nothing already built changes.

Extension pointWhat a new one providesFirst versionAdded later
Protocol driverA program that answers four requests: discover (find devices), browse (list a device's points), read (a batch of points) and subscribe (optional change-of-value). It talks to the core with JSON lines over stdin/stdout, so it can be written in any language.BACnet/IPMS/TP, Modbus, Niagara, Haystack, SNMP, LON, ARCNET
DestinationWhere readings go: takes a batch, returns "stored". The buffer only clears after that.Central server (HTTPS)Trend Tracker on the same box (full on-site mode), CSV/ZIP file drop
ConnectionHow the box reaches HEAPY.Outbound HTTPSVPN tunnel, cellular modem
Hardware profileWhich ports and adapters a box has, so the setup page only offers drivers the box can run.VM (IP only), Pi 5Industrial x86 with LON and ARCNET cards

Point address (one format, any protocol)

bacnet://1201/analog-input:5
bacnet://20014/analog-value:3
modbus://meter-1/holding:40001?type=f32&unit=1
haystack://jace-1/@p:site:r:2c1f
snmp://ups-1/1.3.6.1.4.1.318.1.1.1.2.2.3.0
lon://node-12/nvoSpaceTemp

Each driver owns its prefix. The key holds the device's own id (the BACnet device number), never its IP address or trunk address, so a device that moves keeps its history. Where it is reached now is kept separately as its route (10.77.0.11, or 2001:5 for network 2001, MAC 5).

Driver contract (JSON lines)

→ {"id":3,"op":"discover","timeout_s":5,"rate":10}
← {"id":3,"event":"device","data":{"key":"bacnet://1201",
   "route":"10.77.0.11","name":"AHU-1",
   "vendor":"Johnson Controls","model":"FEC2611"}}
→ {"id":4,"op":"browse","device":{...},"rate":5}
← {"id":4,"event":"point","data":{"key":"bacnet://1201/analog-input:1",
   "name":"AHU-1.SA-T","units":"degrees-fahrenheit"}}
→ {"id":5,"op":"read","device":{...},"points":[...]}
← {"id":5,"ok":true,"result":{"values":[{"point":"...",
   "t":1790702429558,"v":54.38}]}}

The core handles schedules, rate limits, retries and the buffer, so drivers stay small.

Trend Tracker

How it joins the existing platform

Data source"HEAPY Edge" becomes a third data source next to "Novant" and "Manual import". Each site box is a source, and each BAS device is a device under it.
Naming and FDDBACnet object names, descriptions and units go through the same naming library (3,806 learned names today), so equipment trees, standard names, FDD, alerts and reports work with no changes.
New pagesSites and boxes: online / last seen, upload backlog, errors, version. Discovery: devices and points found, with check boxes to choose what to trend and at what interval. Pair a box: one-time code.
Replacing NovantSite by site: install a box next to the Novant gateway, run both for 30 days, compare values point by point in Trend Tracker, then switch the project's live source to HEAPY Edge. Novant history already in Trend Tracker stays.

Risks

What could slow it down

RiskPlan
Client IT approvalOutbound-only design, two-port option, read-only, and a one-page security sheet that answers the usual questions up front.
Load on old controllersPer-device rate limits, batched reads, scans in off-hours windows, and a slower default for MS/TP devices.
Points not exposedSome vendor points only exist inside the vendor's front end. Niagara and Haystack drivers, or exports through Manual import, cover those.
Box failures on siteSSD instead of SD card, watchdog restart, health alerts in Trend Tracker, and a spare-box swap that restores its setup from the server.
Central serverNeeds a host and an owner before Phase 2. Phase 1 can finish on the simulator in the meantime.
